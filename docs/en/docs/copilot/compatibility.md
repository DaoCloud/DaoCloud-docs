# Compatibility

This page lists the compatibility test results between Token Factory Copilot Agent and Kubernetes clusters to help you choose an appropriate cluster version.

✅: Test passed; ❌: Test failed or not supported; Blank: Not tested.

!!! note

    **Testing notes:**

    1. Compatibility tests are based on the Copilot kind E2E suite. The CI scheduled pipeline runs the versions as parallel matrix jobs: each version creates its own one-off kind cluster, installs the images and chart built by the current pipeline, and runs the smoke test cases that cover installation, liveness, and basic capabilities.
    2. Before creating the cluster, each version's job also runs the static install-form contract checks (`helm template` + `yq`). This part is independent of the cluster version, and a failure on any version is treated as not supported.
    3. The extended install-form scenarios (inline Secret, dceAuth, PVC persistence + Recreate, clientConfig delivery) are not part of the compatibility run. They are covered by the regular kind E2E pipeline.
    4. Tests use kind v0.33.0 or later. The `kubeadm.k8s.io/v1beta3` configuration generated by older kind versions is no longer accepted by K8s 1.37.0 and later, and cannot load images into containerd 2.x nodes.
    5. Tests use an in-cluster mock model and placeholder tokens throughout, so real model services and real DCE login are not covered. NetworkPolicy and the platform gateway subpath are disabled in the kind environment; these capabilities are covered by static test cases and UI automation.
    6. In production, choose a cluster version based on the CNI, storage, and gateway capabilities you actually use, and make sure the Kubernetes version is still within its maintenance window.

    **Supported Kubernetes versions:** v1.23.17, v1.25.16, v1.27.16, v1.29.4, v1.33.0, v1.35.0, v1.36.1, v1.37.0.
